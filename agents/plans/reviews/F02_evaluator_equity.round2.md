ROUND 2 REVIEW of `agents/plans/F02_evaluator_equity.md`

B1 [major] §3.3 river exact path / §5 budget guarantee — Exact enumeration runs to completion based solely on a fixed local estimate of 6 microseconds per pair. With 903 pairs and a 6 ms budget, it selects exact enumeration, but at 20 microseconds per evaluation the evaluations alone take about 18 ms. This violates the promised deadline-plus-one-CHECK_EVERY-block bound and the shared interface's requirement to stop on time. A bank reserve does not enforce the per-call deadline. — Keep finite-budget river calls interruptible, with a valid weighted-sampling estimate available if exact work cannot finish, or restrict mandatory complete enumeration to explicit unlimited-budget calls. Include preparation time in the deadline and add a slow-evaluator/fake-clock test for a finite-budget river call that passes the upfront cost estimate.

B2 [minor] §6B.5 scale invariance requires identical results — Rescaling floating-point weights can change their ratios by rounding, even when all inputs remain finite. For weights [1, 3, 7] and showdown values [0, 0.5, 1], max-normalized weighted equity is 0.7727272727272727 at scale 1 and 0.7727272727272728 at scale 1e-300 using ordinary Python arithmetic. An exact-equality assertion can therefore fail for a correct implementation. — Use a tight numerical tolerance for exact equity and n_eff across scales. For sampling, use controlled draws away from cumulative boundaries or distributional checks. Preserve exact fixed-seed format equivalence for representations containing the same numeric weights in the same canonical order.
